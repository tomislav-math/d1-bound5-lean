This is a supplemental evidence recipe, not a theorem, build, audit, or kernel acceptance gate. It implements the already selected explicit archival scope and optional XZ3 amendment. Only synthetic fixtures have been captured so far; future real inputs must be selected and authorized by the coordinator after their writers stop.

The two actions are `capture --plan ABSOLUTE_JSON --plan-sha256 SHA --out NEW_ABSOLUTE_DIRECTORY` and `verify --package ABSOLUTE_DIRECTORY --manifest-sha256 SHA --out NEW_ABSOLUTE_DIRECTORY`. Invoke the reviewed script by absolute path using Python 3.8 or later. No Lean, checker, Git, source, build or runtime command is invoked. No network or subprocess is used by the recipe.

The plan contains exactly schema=1, phase=1/2/3, a simple label, files, missing, and inventories. Each file is an explicit {source:absolute_path, logical:relative_path, bytes:integer, sha256:hex, status:COMPLETE_ORIGINAL or PARTIAL_NOT_TERMINAL}. The status describes which original bytes were retained, never whether a proof passed. A missing item is {source:absolute_path, reason:text}; it remains absent, and no substitute result is manufactured. Each inventory is {root:absolute_directory, entries:[{path:relative_path, disposition:include/exclude, reason:text}]}. Every regular member of a named terminal directory must appear, including reasoned exclusions; symlinks and special files are refused. Included entries must have corresponding file rows. Directory inventories are explicit rather than recursively inferred from broad live build roots.

Capture requires the pinned original bytes and unchanged source stat/hash before and after all reads. It writes only an absent destination, refuses overlap with sources, missing paths, inventory roots, its own script or plan, and fsyncs files plus new directory/parent entries. A failure leaves an incomplete destination for inspection; it is not reused or relabelled complete. No original evidence is reserialized. PLAN.json is copied byte for byte; MANIFEST.json is a new record.

Small NUL-free UTF-8 originals below 5 MiB are copied directly. Larger and binary originals use contiguous ordered base64 parts. Phase 1 retains the original raw format. For large phase 2/3 originals, standard single-stream XZ preset 3 / CRC64 is selected only when the measured encoded length is smaller; otherwise raw parts are retained. Decoded chunks are at most 3,145,728 bytes. Canonical RFC4648 base64 is wrapped at 76 columns with LF; each stored part is at most 4,249,493 bytes, below the strict 5,242,880-byte Git limit. Encoding identity, original/encoded/part lengths and SHA256 values are recorded. Python's lzma implementation/version and selected preset/check are recorded for XZ.

Every captured original is locally reconstructed before the final manifest is written. The independent verify action can run on a different machine after the original source paths disappear. It validates the same recipe hash, pinned plan/manifest, exact package membership, schemas, explicit directory snapshots, source/stat bindings and all encoded parts. Its decompressor has a 64 MiB memory limit and bounded output; it requires one complete CRC64 XZ stream with no trailing bytes or concatenated stream. Full original length/SHA are checked during decoding and again by reading the fsynced destination. It creates a new RECONSTRUCTION.json receipt only after all original bodies and unchanged package inputs pass. A source-only hash-pinned copy of this script and an independently supplied manifest hash must be used on the destination.

All semantic package files, ordered base64 parts and verification receipts are permanent evidence. They belong in the exact Git publication allowlist; they are not disposable transport. Large reconstructed originals can live in the separate proof-object store, outside Git. Transport envelopes and chunks are separate from these semantic parts. A plan or manifest at or above the strict text limit fails closed; explicitly partition the selected scope into separately labelled small packages instead of omitting rows. Capture each terminal invocation's original records, including failed or interrupted attempts, and retain actual raw tool-return truncation metadata. Never call an unsaved/reconstructed driver transcript an original.

The selected three-phase timing remains unchanged: preserve each terminal build invocation; preserve complete exact118/broad logs and input freezes plus final kernel freeze before a long fresh checker; preserve actual terminal checker logs/results/memory/tool returns afterward. Root still owns launch decisions. Accepted artifact checkpoint archives remain a separate chain; this recipe does not mark supplemental records or partial artifacts as accepted modules. It does not relax the requirement that complete artifact and audit/freeze bodies be durably verified before the long final run.

These guards assume coordinated nonhostile writers, with the coordinator stopping terminal evidence producers and preventing concurrent path replacement. They detect ordinary mutation and reject symlinks/overwrites; they are not a claim of transactional filesystem security against a malicious concurrent root process. fsync improves process/power-loss persistence on the underlying filesystem but cannot promise storage hardware durability beyond the OS contract.

Cross-machine boundary: during verify, recorded original source/missing/inventory paths are historical identities and are protected lexically. They are not required to exist or be resolved through the destination machine's unrelated symlinks (for example Linux /tmp versus Mac /private/tmp). The actual local package, recipe and new output paths remain canonical, symlink-free and exclusive. Choose a newly owned proof-object output root, not an alias intended to recreate an original path; this helper does not infer a same-host path-provenance model for foreign recorded strings.
