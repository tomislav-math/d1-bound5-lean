# Graph46 closure execution workflow

This directory prepares the guarded closure workflow for the actual graph46
sources. The source-only remote inspection and proposal generation have passed.
No graph46 executable installation binding, bounded build, audit, replay,
endpoint acceptance, or publication is supplied by this local preparation.
The frozen source scripts, previous graph1 files, and graph46 foundation and
side preparation files are unchanged.

## Required completed prerequisites

Installation requires the actual completed and privately published graph46
foundation and both sides. The four prerequisite scopes are `foundation`,
`sides-pilot`, `left-rest`, and `right-rest`. Their target and declaration counts
are derived from the actual foundation binding and frozen side proposal, then
cross-checked against the reviewed interfaces.

The foundation preparation is reproduced through its pinned pure
`foundation_inputs.verify_prepared()` helper. The side foundation binding must
contain the exact 26 paths defined by the frozen side installer. Every required
source, receipt, proof state, original declaration, axiom audit, kernel replay,
source map, artifact and configuration is checked at its current bytes.

Both prerequisite publications must have actual `PRIVATE_PUSH_VERIFIED`
receipts, successful commit and push exits, equal local and remote heads,
private repository identity, exact selected committed blobs, and inactive,
released owners. Their commits must be ancestors of the actual closure intake
HEAD. Post-push receipt, owner and release files are separately bound by their
actual hashes; they are not required to appear in the commits they describe.

The reusable prerequisite checks do not require an earlier phase's installation
HEAD to remain current. Phase execution itself is bound to the closure intake
HEAD and index bytes.

## Binding and source installation

The binder command interface is:

```text
python3.12 -B bind_inputs.py HEAD QUEUE_SHA INSPECTION_SHA PLAN_SHA PAYLOAD_SHA [EXTRA_MAP ...]
```

All five required arguments must come from reviewed actual observations. The
three source-evidence arguments must equal the fixed actual hashes above.
Extra source maps must be repository-relative, currently hash-matching and
committed. The four graph46 prerequisite maps and the completed-checkpoint map
are required. A separately supplied committed map can cover any remaining
external dependency, including `PairClosureIndexedChunks`. Missing provenance
stops binding.

The binder holds both existing project locks, requires an idle driver and no
live project compiler, and checks the `main` branch, clear index, actual HEAD,
paused single-worker queue, unchanged root and pinned configuration. It records
the current accepted endpoint inventory directly from the existing driver. It
does not assume any previous endpoint count or list. It writes only new
`INSTALL_BINDING.json`, `PROVENANCE_BINDING.json`, and `BINDING_EVIDENCE.json`.

The installer requires the separately reviewed SHA of the actual installation
binding. It repeats the exact proposal, prerequisite and source checks, computes
all proposed dependency closures, and rejects any previously attempted exact
target fingerprint before changing project files. It preserves the complete
existing receipt prefix and baseline, all historical graph46 target receipts,
and every available original attempt log and source sidecar in
`installation/ORIGINAL_ATTEMPTS_BEFORE.json`.

Only the original merged graph46 module is replaced with the exact archived
facade. The other 24 reviewed modules are new files. The existing queue is
extended only with those 24 names; all other queue fields remain byte-for-byte
equivalent after canonical serialization. Original sources and candidates are
preserved in the research directory. No historical receipt, trusted baseline,
Git state, canonical root, or accepted proof is changed by installation.

## Serial builds, audits and replays

The actual closure proposal defines these scopes:

| Scope | Targets | Definitions | Theorems | Declarations |
| --- | ---: | ---: | ---: | ---: |
| `closure-pilot` | 4 | 9 | 2 | 11 |
| `closure-rest` | 12 | 0 | 13 | 13 |
| `assembly` | 9 | 4 | 13 | 17 |
| Closure total | 25 | 13 | 28 | 41 |

For each scope, run the reviewed controller, prepare its exact audit inputs,
use the existing pinned scoped audit runner to bind and run the type/axiom
check and every same-kernel replay, and then run the finisher. A completed
scope is required before the next scope starts. Direct worker execution also
checks the preceding completed scopes.

The controller and worker retain both project locks at the protected launch and
verification boundaries, one compiler and one Lean thread, paused queue state,
and the unchanged **240-second inner target timeout**. Each worker refuses a
prior exact attempt, freezes source and artifact dependencies, and drains its
compiler child on stop. Controllers keep durable batch records and do not
resume a failed or interrupted batch under the same identity.

Audit preparation constructs examples at each exact original public type and
collects transitive axioms. The allowed axiom list remains `propext`,
`Classical.choice`, and `Quot.sound`. The finisher requires actual successful
bounded build receipts, both source snapshots, exact current accepted
artifacts, exact declaration coverage, all bound audit and replay receipts, and
unchanged guard maps. The runner's preparation-file guard includes the saved
binding's actual self-hash in addition to the serialized file map.

The original final graph46 statement remains:

```lean
theorem smallPairNoTriangle_46_checked :
    pairGraphTriangleFreeBool smallPairSieve_1_6 smallPairLarge_46 = true
```

Scope finishers keep `whole_graph46_complete`, `root_integration`, and
`main_theorem_complete` false. A scope result is not an endpoint result.

## Endpoint collection and current inventory

The endpoint collector requires all seven verified scopes: four prerequisites
and three closure scopes. It derives the complete target and declaration
totals from the actual phase inputs and closure proposal, requires disjoint
target and declaration coverage, and rechecks the accepted current endpoint,
its original theorem, source closure, audit records and protected artifacts.
Only that completed check can produce a graph46 endpoint proof state.

The separate read-only inventory uses the actual baseline recorded in the
installation binding and the current driver acceptance of all 48 endpoints.
It reports actual additions and removals and whether the expected addition of
graph46 is observed. It does not impose the new seven-scope layout on historical
endpoints or turn endpoint counts into an overall proof-completion percentage.
The canonical root and the main theorem remain unintegrated and unproved by
this workflow.

## Review limits and remaining measurements

Local review covers syntax, pure imports, fixed actual source pins, regenerated
worker syntax, exact scope interfaces, historical-receipt preservation and
cross-script consistency. It is not a Lean or kernel test. Graph46 compiler and
replay timings remain unmeasured. In particular, the exact right-row fragment is
618,584 bytes; its actual accepted bounded build must justify continuing under
the unchanged cap. A timeout or failed fingerprint is retained and is never
silently retried.
