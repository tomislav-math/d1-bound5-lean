## Reusable source-only staging checklist

These checks implement the existing policy and explicit publication scope;
they do not introduce a compiler run or replace the actual proof checks.

1. **Actual scope evidence.** Confirm completed build, exact statement/axiom
   audit and replay receipts for this scope, then compare their source,
   artifact, configuration and proof fingerprints with the current files.
   Preserve the precise difference between a scope, a working endpoint and
   canonical-root integration. Use no placeholder binding or proof hash.
2. **Quiet ownership.** Begin from an empty index with the existing driver and
   intake locks, no active compiler/replay or publication owner, and the
   reviewed current HEAD. Preserve earlier failed/expired owner records;
   create a new owner in the new publication directory.
3. **Concrete selection.** Inspect the guard-generated
   `SELECTED_FILES_SHA256.json` and `STAGING_PATHS.txt`. The latter must be
   exactly the selected-map keys plus the two selection files themselves,
   without duplicates. Every selected file must match its reviewed bytes.
   The guard also collects bound preparation files and recursively collects
   scope/audit files, so research-only `extra` entries alone do not guarantee
   that every generated selection path belongs to the intended archive.
4. **Exact index equality.** Stage only the explicit reviewed list in a
   separate plain Git call. Compare the complete actual staged path set with
   that list and compare every staged blob with the reviewed SHA-256. For
   this archive-only publication there must be no additional canonical
   `D1Bound5/` paths, binaries, unrelated trials or newly broadened scope.
   A mismatch is a failed snapshot requiring a separate review; do not
   silently add files, filter a failed result or refresh proof manifests.
5. **Existing index and private preflight.** Run the unchanged exact-index
   helper and ordinary private-repository preflight against the actual
   selected snapshot. Both must pass their applicable checks. Retain their
   real outputs. A source fingerprint records bytes and does not establish
   compilation, exact statements, kernel replay or root integration.
6. **Preserve proven bytes.** Inspect the actual diff and whitespace findings.
   Record relevant findings without rewriting evidence or source snapshots
   merely to remove whitespace warnings. Any source change would invalidate
   the matching recorded proof fingerprint until separately verified.
7. **Separate publication and completion.** Perform the ordinary commit and
   non-forced private push as separate reviewed tool calls. Obtain their
   actual completion results, compare committed selected blobs, actual
   remote main, private visibility and the final index, then write the
   truthful post-push receipt and release the owner. A started process or an
   old successful receipt is not the current operation's completion.

The graph1 recovery illustrates step 4: the original selection was exactly
394 archive paths, while the index additionally contained 25 canonical paths.
Those extras were absent from HEAD and preserved identically in both archive
copies. A separately reviewed exact unstage repaired that particular selection
mismatch. It does not authorize automatic recovery or a blanket exception for
future snapshots.
