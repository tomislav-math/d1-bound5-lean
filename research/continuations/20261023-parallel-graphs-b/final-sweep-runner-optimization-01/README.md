# Final-sweep artifact inventory optimization

This is a separate research-only revision of the reviewed fresh-project builder. The original `fresh_project_build.before.py` is byte-identical to runner SHA256 `d2b952a6e59bcaf4a55d172bf64996bbc8ce3d661ca2972ff4018690d096dd66`. No production Lean source, canonical tool, old receipt, Git state, or existing build origin is modified by this package.

The optimization applies only after `ThreadPoolExecutor.shutdown(wait=True)` and successful completion of every selected module. Active compilation, publication, live dependency checks, and resume validation retain the original live filesystem lookup. Final runtime inventory/hashes, source/configuration pins, accepted receipt and log hashes, every transitive dependency check, and every existing `Pins.verify` call remain in place.

The final sweep creates a complete directory/file metadata snapshot once, indexes each directory's sorted file names, and uses binary searches for the exact existing `.olean*` and `.ir*` prefix semantics. It does not substitute metadata for expected content hashes. Every bundle still has its exact membership compared with the accepted receipt and every expected file is verified by `Pins.verify`. The final snapshot includes all entries, including names not selected by a bundle. Symlink and special-file artifacts are rejected explicitly in this final phase.

Snapshot construction records device, inode, mode, size, nanosecond mtime, and nanosecond ctime. Each directory is checked before and after enumeration; every collected entry is checked again before construction returns. After the whole final sweep, a second full snapshot must have identical metadata and membership before success can be written. Insertions, deletion, renames, replacements, and content or mode changes are rejected. Coordinated filesystem writers and the existing build lock remain prerequisites; this is not a security boundary against a hostile privileged filesystem writer or hardware filesystem corruption.

Historical measurements motivating this change: 4,406 selected modules, 122,319 transitive-ancestor visits, and 126,725 final bundle guards. The former helper scans each flat directory twice per guard. Historical wall time for the whole previous final sweep was about 12 minutes 48 seconds. This revision removes those repeated directory enumerations; it retains all repeated hash-pin checks. Fixture timings are not a full-project performance or Lean verification claim.

This new runner has a different content hash and therefore a different build identity. It requires a new initially empty build directory and its own source/runtime/runner identity; it cannot resume receipts made by the original runner. Any separately pinned audit or release tool must receive an explicit reviewed new hash, rather than weakening or silently bypassing its old pin. The parent coordinator decides whether to use this revision. No Lean build or official checker is authorized or launched by this preparation package.

Acceptance evidence is recorded separately in the test reports, independent review, and package manifest. Fake-compiler lifecycle tests and temporary filesystem fixtures make no Lean theorem claim. Before use, the exact reviewed package must be saved and hash-verified in the repository's owned research directory on the Mac.
