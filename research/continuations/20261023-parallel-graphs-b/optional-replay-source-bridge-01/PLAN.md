# Optional source snapshot bridge — preparation only

This proposal is not selected, installed, frozen against the real build, or executed. No Lean/compiler/checker is launched by its preparation or fixtures. The original e04 supervisor and all historical build/audit records remain unchanged. The recovery build must finish and both exact 118 and separate broad compatibility audits must pass before a real bridge manifest can satisfy this helper.

The distinction is explicit: `original_compile_root` is the literal absolute path preserved in ORIGIN and every original compiler/audit argument; `replay_source_root` is a separate clean Git checkout with identical committed bytes. The checker works from the latter. No original receipt, invocation, source freeze, or Git identity is relabeled or rewritten. An exact retained-file mapping describes byte-identical copies of historical metadata whose old locations may disappear.

The fixed supported candidate is b4c81242dd9c9cee6966a1e08bce0f94c66f1491/tree ee490da49ba30447d92745140f48c1ae3c34f263. Its source lock is b3be4592f1c30e40abb6677cb5319d0420538adb20f6d05e743205be19d59d3c: 4,406 production modules, three configuration pins, and two immutable Lean audit harnesses, exactly 4,411 tracked regular files. Any different candidate requires a separately reviewed revision, not an override flag.

`freeze` alone accepts the paired arguments `--source-relocation-manifest PATH --source-relocation-sha256 REVIEWED_SHA256`. They are rejected on `plan` or `run`, or when only one is supplied. A manifest does not establish its own authority: its exact hash must be separately reviewed and passed explicitly. No real manifest is supplied by this preparation package. Values for completed summaries and future audit logs do not yet exist.

Manifest schema 1 requires exactly these fields: `schema`, `kind` (D1BOUND5_REPLAY_SOURCE_RELOCATION), `original_compile_root`, `replay_source_root`, `artifact_root`, `distribution_root`, `candidate_commit`, `candidate_tree`, `source_lock_sha256`, `runtime_lock_sha256`, `source_inventory_sha256`, `build_origin_sha256`, `build_summary_sha256`, `build_id`, `build_identity_hash`, `records`, and `retained_files`.

`records` has exactly nine roles: `exact_summary`, `exact_input_freeze`, `integration_log`, `target_log`, `broad_summary`, `broad_evidence_freeze`, `broad_log`, `source_policy_report`, `source_policy_manifest`. Each value is an unchanged historical absolute filename, also a key in `retained_files`. Each retained row has exactly `{ "path": "/tmp/.../retained-copy", "sha256": "reviewed hash" }`. Historical source/config/harness paths map mechanically from the original compile root to the replay root; they must not be redundantly listed as retained rows. Historical runtime/build paths remain identical and must match current frozen pins. Other historical metadata/helper/lock/invocation paths require explicit retained rows. Every retained row must be used, and duplicate destination aliases are rejected.

The new freeze schema 4 contains the manifest hash and its validated context, duplicate source/Git identities, original build provenance, exact accepted receipt-chain and artifact-bundle identities, retained audit/source-policy records, and all existing runtime/artifact/config inputs. Every live pin must reside under `/tmp`, so neither the original source workspace nor sibling historical helper paths remain live dependencies. The new helper and bridge manifest are themselves pinned. Old schema 3 and unrelocated behavior are retained.

All existing receipt status, source hash, exact compiler argv, dependency-chain, log, artifact, external cache, runtime, compiler, loader, package-owner, source/config and empty-build-origin checks remain. Completed build evidence is required, including its original final-integrity success summary. The historical exact audit input freeze must match the same source/config/harness map, Git candidate, original environment, original build identity, accepted chain and artifact bundles. The broad summary/log/freeze must bind those exact audit records. The source-policy evidence is the independently reviewed source-only report and full exact production map; it is not presented as a new Lean run.

New checks reject additional/changed/missing source files (including ignored files), symlink aliases, nonregular files, changed committed blobs even when Git flags might hide worktree changes, wrong original roots, altered compiler/audit argv, changed or incomplete accepted records, extra isolated artifact sidecars/junk, inconsistent snapshots, missing/mutable mappings, and old live workspace pins. The replay source/Git snapshot is captured twice during freeze and revalidated before and after replay. The complete artifact/runtime and provenance hashes retain their existing pre/post validation. This assumes coordinator exclusion of other writers; it is not a hostile filesystem sandbox or a replacement for operating-system integrity.

The official Lean 4.33.1 checker binary, command construction, `--verbose --fresh D1Bound5`, LEAN_NUM_THREADS=0, resource watchdog, timeout, OOM handling, exact banner, return-code and post-run identity checks are unchanged. The entire `execute` function is AST-identical to e04. Kernel replay and exact type/transitive-axiom audits remain separate gates; this optional bridge binds historical accepted audit evidence and does not rerun those Lean audits.

Before any real use: review the final helper/tests/manifest and durable package; complete the unchanged-source build and current exact/broad audits; retain their exact metadata outside the volatile workspace; populate and independently review a new manifest; run only freeze first; inspect that no live pin depends on the old workspace; then let the parent choose whether to run the new optional supervisor. Existing e04 remains available and unchanged. No end-to-end execution or mathematical acceptance is claimed by this document.

The existing CHECKER_LOCK remains beside the executing helper. Different helper revisions in different directories therefore have distinct lock files; the root coordinator must exclude concurrent checker launches across versions. The retained resource admission check is not a universal cross-version mutex.

The retained Git object/configuration storage must also be standalone: symlink/special Git metadata, common-directory indirections, shallow/partial/promisor stores, external object alternates, and configuration includes are rejected. This prevents hidden dependencies on a disappearing workspace even when selected source blobs themselves remain correct. See MAPPING_PREPARATION.md for the explicit post-gate preparation recipe.
