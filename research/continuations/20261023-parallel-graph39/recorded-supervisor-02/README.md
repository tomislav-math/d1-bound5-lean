This is a narrow process-observation revision for future, separately selected recorded invocations. It is not a guardian, watchdog, proof gate or platform-survival mechanism. The currently running original supervisor4863 and its evidence remain unchanged.

The observed environment gives Python a namespace-local `os.getpid()`/`Popen.pid`, while its mounted `/proc` exposes host IDs. The original CHILD record could therefore combine a local child PID with an unrelated host `/proc/<pid>/stat` start time. Revision02 labels namespace-local IDs explicitly. It reads the supervisor host identity from `/proc/self/stat` plus status/NSpid, and scans host proc entries for one stable child with the expected host PPid, namespace-local PID, namespace depth and PID namespace. Missing, inaccessible, raced or non-unique observations are recorded as UNAVAILABLE. A short-lived child can legitimately finish before observation.

Host stat parsing handles spaces and parentheses in the comm field. The child record never resolves `/proc/<Popen.pid>` merely because that number is the local Popen PID. These observations are optional metadata; the original `Popen.wait()` remains the authority for the actual child process return. Host process identity is meaningful only at observation time, so later inspection must recheck start ticks, exact command and namespace context.

The selected argv, cwd, driver SHA checks, Popen call, inherited driver environment, file-backed stdout/stderr, child wait, log SHA and actual-return semantics are unchanged. The wrapper does not launch raw Lean/checker processes itself or change an enclosed driver's resource/admission/watchdog settings. The AST scope report records identical sha/utc/write functions and identical Popen/wait call ASTs; only run metadata and four new observation functions differ. Future actual invocation requires the coordinator's review of the concrete spec SHA and selected driver identity.

Use `python3 recorded_supervisor.py ABSOLUTE_SPEC_JSON EXPECTED_SPEC_SHA256`. The explicit spec schema remains argv/cwd/out/driver_sha256, with a new canonical absent output directory. This package does not execute or preselect an actual proof invocation. Fixture runs use only temporary small Python children.

Limitations from the original wrapper remain: detached execution does not guarantee survival of tool/session cleanup or platform-wide termination; a post-launch I/O/Python failure may leave a driver alive without an ACTUAL_RETURN; inspect process ownership and driver lock before any retry. Missing terminal evidence means UNKNOWN. Files/output directory are fsynced, but the newly created output directory's parent entry is not explicitly fsynced. The final stdout hash reads that log into memory; the selected invocation must have suitable output/resource expectations. These are operational records, never acceptance based merely on PID, exit code or a stale summary. Full proof checks remain separate.
