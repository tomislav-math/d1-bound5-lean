# Prove2Me Field 7 publication recovery

The locally verified Lean theorem was unchanged. A Prove2Me definition
publication remained COMPILING for more than six hours. The author requested
a replacement under a different platform name, followed by rerouting only
after the replacement succeeded.

An exact byte-for-byte alias returned a token-scanner timeout after ten seconds.
The successful replacement splits the two large literal lists into 49 typed
slices. Their entries and order are preserved exactly. The three original
auxiliary theorem bodies are unchanged and were checked as part of the
replacement definition publication. All 50 replacement definitions were
PUBLISHED before the consumer was redirected.

Only one never-submitted consumer import changed. The other 8,841 existing
ledger entries and all recorded successful proof submissions were preserved.
The old server job was retained in the audit history as a superseded job,
not cancelled or reported as successful.

- `ACCEPTED_DEFINITIONS.json` records the successful platform IDs and source hashes.
- `REPLACEMENT_MANIFEST.json` and `sources/` contain the submitted replacement code.
- `PROVENANCE.json` contains the original code and exact ordered-list reconstruction evidence.
- `MIGRATION_RESULT.json` records the checked transition of the upload ledger.
- `tools/` preserves the preparation, validation and migration programs.

The transfer tools require the existing authorized local client and live transfer
workspace for network operations. No client credentials are included.
The source imports target Prove2Me modules in the pinned Lean/mathlib environment.
This record does not by itself assert completion of the entire Prove2Me mission.
